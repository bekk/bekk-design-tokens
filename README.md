# Bekk design tokens

Design tokens for Bekk, kept in sync with Figma through the **Token Spark** plugin. The JSON in `tokens/` is the source of truth; everything else is generated from it.

```
tokens/              Source of truth (W3C DTCG JSON)
  primitives/          Raw values: the colour palette, and sizes (mobile / desktop)
  semantic/
    themes/            One file per brand theme: Vann, Jord, Ild, Luft
    light.json         Meaning-based colours (text, bg, surface…) for light mode
    dark.json          …and for dark mode
    global/            Typography styles (leading, body, heading, action…)
  metadata.json        Themes, colour schemes, sizes, Figma mapping, output formats
dist/                tokens.css · tokens.js · tokens.ts   (generated)
ios/                 DesignTokens.swift                   (generated)
lib/src/             design_tokens.dart                   (generated)
```

## How the colours fit together

```
primitives      →   theme (Vann)                →   semantic
color.grey.100      color.light.base.brand.default  color.base.brand.default
```

A **theme** picks which palette colours play which role, once for light and once for dark. **Semantic** tokens (`color.bg.default`, `color.text.default`…) are what you use in code — they follow whichever theme and colour scheme is active, so components never reference a brand or a mode directly.

## Using it

### Web

```html
<link rel="stylesheet" href="dist/tokens.css" />
<html data-color-scheme="auto"></html>
```

```css
.card {
  background: var(--color-bg-default);
  color: var(--color-text-default);
  border-radius: var(--primitive-radius-md);
}
```

| Attribute | Values | Notes |
| --- | --- | --- |
| `data-color-scheme` | `light` · `dark` · `auto` | **Required** — semantic colours only exist inside it. `auto` follows the OS setting. |
| `data-theme` | `vann` · `jord` · `ild` · `luft` | Optional — `vann` is the default. To theme just one section, put `data-theme` **and** `data-color-scheme` on it — `data-theme` alone doesn't change the semantic colours. |
| `data-size` | `desktop` | Optional — desktop sizes switch on automatically from 768px; set this to use them at any width. |

### JavaScript / TypeScript

```ts
import { tokens, themes } from "./dist/tokens";

tokens.light.color.text.default; // "#1f1f1f"
themes.vann.color.light.bg.default; // "#ffffff"
```

### iOS and Flutter

`ios/DesignTokens.swift` and `lib/src/design_tokens.dart` have one type per theme and colour scheme — e.g. `DesignTokensLight.colorBgDefault`, `DesignTokensThemeVann`.

## Changing tokens

Designers change variables in Figma, then run **Token Spark → Push to GitHub**. That opens a pull request containing the updated `tokens/` and all generated files — review and merge it like any other change.

`dist/`, `ios/` and `lib/` are only regenerated by a push, and the next push overwrites any hand edits — so change tokens in Figma (or edit the JSON and **Pull** it into Figma), not in the generated files.

> `$themes.json` and `$metadata.json` in the root are leftovers from Token Studio. Nothing here uses them.
